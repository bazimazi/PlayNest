# Languages in PlayNest

English is the source language and Persian (`fa`) is the second. Everything here applies to adding a third.

The language is settled before anything else runs (`src/main.tsx` awaits `initLanguage()`, then imports the app), and changing it
reloads the app. So there are no hooks or providers: `t()` is a plain function, and it is safe in a module-level constant.

## Writing code that shows words

Import from `src/i18n` (`rich` from `src/i18n/rich`).

| You have | Write |
|---|---|
| Any word a person reads, including `aria-label`, `title`, `placeholder`, `alt` and toasts | `t('Save')` |
| A value inside a sentence | `t('{name} is ready', { name })`. Never join pieces of a sentence with `+` or a template: word order differs between languages |
| A count | `tn(n, '{n} play', '{n} plays')`. `{n}` is filled in for you |
| An element inside a sentence | `rich('Saved for <name/>. <link>Change</link>', { name: <b>{n}</b>, link: (s) => <Link to="/x">{s}</Link> })` |
| A number outside `t()` | `num(n)`. Numbers inside `t()` params are converted for you |
| A date | `formatDate(d, options)`, never `toLocaleDateString(undefined, …)`. A day or year shown alone is `formatDate(d, { day: 'numeric' })`, never `getDate()`: in Persian the calendar differs too |
| A date a parent enters | `<DateField>`, never `<input type="date">`. Dates are stored as Gregorian `YYYY-MM-DD` in every language |
| A number a parent types | `asciiDigits(value)` before reading it, because Persian keyboards type Persian digits |
| A phone number on screen | `<span className="ltr">{localDigits(number)}</span>`. `telHref` copes with any digits; the data stays ASCII |
| Sorting words | `compareText(a, b)`, never `localeCompare` alone |
| A comma-separated run of items | `commaList(items)`, never `.join(', ')` |
| One English word with two meanings | `tc('audio', 'Play')`, translated under the key `audio|Play` |
| The day of the month on its own | `dayOfMonth(d)`, never `getDate()` |
| Comparing what someone typed with text | `foldText()` on both sides: Arabic and Persian keyboards type different letters for the same word |
| A name in its own script under a title | Show it only if `showsOwnScript(name)`: in Persian, a Persian name would repeat the title |
| A proper name or citation that stays as written | `translate="no"` on its element |
| A string nobody reads that looks like words | `// i18n-ignore` on or above the line |

The first argument of `t` and `rich`, and the second and third of `tn`, must be plain string literals. `src/i18n/i18n.test.ts` reads the
source with the TypeScript parser. It fails on words on screen that aren't marked, on non-literal keys, on missing or unused translations,
and on translations whose placeholders differ.

## Deciding things by reading words

Code that decides something from what content says (which help lines are urgent, which interests a game touches, which other first-aid
card a step names) must read the English, or it would break silently in every other language. `english(holder)` gives back the English
version of an array or object of content:

```ts
const helpInEnglish = english(s.help);
const urgent = s.help.filter((_, i) => URGENT_LINE.test(helpInEnglish[i]));
```

What a parent types is the exception: search has to understand Persian itself, so `src/lib/search.ts` keeps Persian word lists beside the
English ones.

## Layout

- Use logical CSS: `margin-inline-start`, `inset-inline-end`, `text-align: start`. Not `left` and `right`, except for something centred
  with `left: 50%` or for decorative art.
- Anything that moves sideways multiplies by `var(--flip)` in CSS, or checks `isRtl()` in code. That covers swipes and arrow keys too.
- Icons listed in `DIRECTIONAL` in `Icon.tsx` mirror by themselves.
- Paragraphs use `unicode-bidi: plaintext` in right-to-left, so a line takes its direction from its first letter. That is why a
  translation must not start with a Latin word.

## Content

Content stays in `src/data` in English. Each module ends with `localize('name', DATA)`, which replaces strings in place as the module
loads, from `src/i18n/locales/fa/name.json`. Keys are dotted paths using each item's `id` or `slug`: `peekaboo-scarf.steps.0`.
`src/i18n/flatten.ts` decides what counts as words; ids, enums and citations don't.

Collections with `{ hideMissing: true }` (games, stories, songs, guides, tips, celebrations) leave out what hasn't been translated, rather
than showing a parent a page they may not be able to read. Everything else must be translated whole.

```
npx vite-node scripts/i18n.ts status                  # coverage of every collection, and what has gone stale
npx vite-node scripts/i18n.ts todo stories out.json   # the English still to do, as JSON
npx vite-node scripts/i18n.ts merge stories in.json   # add translations; reports any that fail the checks
npx vite-node scripts/i18n.ts leaks pages/Today       # words on screen not yet marked
npx vite-node scripts/i18n.ts check stories out.json  # the checks below, without changing anything
```

To translate more, take the English from `todo`, translate it to a file of the same keys, `check` it, then `merge` it. An item that is
part-translated fails the tests, so translate whole games and stories. First aid, crying, crisis and helplines also need a second reader
who compares meaning line by line: see section 8 of [REVIEW-1.5.md](REVIEW-1.5.md) for what one found.

`npm run e2e:fa` walks every screen in Persian. It checks direction, overflow at 320px, accessibility, English left on screen, a Persian
birthday, dialling, arrow keys, the language switch and search typed on an Arabic keyboard.

`src/i18n/hashes/` records which English each translation came from, so changing a sentence fails the tests until it is translated again.
That matters most on a first-aid card, where an old translation of a corrected step would be dangerous.

The tests check every translation mechanically: its numbers match the English, its digits and letters are Persian, and its placeholders
are intact. **They can't tell whether it is right.** See `docs/REVIEW-1.5.md`.

## One culture per language

**Each language uses only its own culture.** The Persian app tells Persian stories, sings Persian songs, keeps Iranian days and plays
Iranian games, and never borrows from Arabic, Turkish, Kurdish, Armenian, English or any other language's culture. The English app
likewise uses only English-language culture. Nothing is shown across: no foreign rhyme, tale, festival or game, and no aside such as
"children in Bengal play a similar game".

- Every story, song and festival carries `lang`, the ISO 639 code of the language whose culture it comes from (`'fa'`, `'en'`,
  `'ja'`…). So does every game with an `origin`, every festival game (the same as its day's), and any game or talk card tied to one
  culture without one, such as an English nursery rhyme (`'en'`) or a Persian proverb (`'fa'`).
- `fitsCulture()` in `src/i18n/index.ts` shows an item only in its own language. Content with no `lang` (most games, the guides, help,
  first aid, talk cards, stages) belongs to no one culture: it shows in every language, translated, and its translation adapts anything
  culture-bound to the reader's own life rather than importing it.
- Items for a culture with no language in the app yet stay in the source, unseen. Add that language and they appear in it.
- Persian-only content still has English source text, because the tooling and tests read it, but the Persian is what parents read:
  write it as Persian first. The modules for it are `activities/iran-young.ts`, `activities/iran-older.ts`, `stories-persian.ts`,
  `songs-persian.ts`, `talk-persian.ts`, `celebrations-persian.ts` and `activities/celebrate-persian.ts`. English-only additions live
  in `stories-english.ts` and `songs-english.ts`, which are never translated.
- The translation tools and tests skip items from another culture (`flatten(name, data, 'fa')`): there is nothing to translate. A song in
  the reader's own language shows its own words without a meaning under each line, so its `lines.*.english` isn't translated either.
- `src/i18n/culture.test.ts` loads the content in each language, as the app does, and checks that nothing foreign shows, that no Persian
  text talks about another culture, and that each language has enough games, stories, songs, tips and days for every age.

## Writing Persian

Standard written Persian, warm and plain, for a tired parent. Reading age about 12. The English house style carries over: no guilt, no
comparison, nothing about a child having "failed" or "missed" anything, and ranges rather than exact ages.

- **Address the parent as «شما»**, with polite plural verbs: «انتخاب کنید», «بغلش کنید». Not the singular imperative, and not stiff or official language.
- **No loan words where a plain Persian word exists.** Short labels stay short.
- **Letters:** Persian ی and ک, never Arabic ي ك ى.
- **Digits:** Persian ۰۱۲۳۴۵۶۷۸۹ in all text. Every number in the English appears, unchanged, in the Persian: the tests check. Spelled-out numbers ("two fingers") may stay as words or become digits.
- **Half-space (U+200C):** می‌شود، بچه‌ها، کتاب‌ها، خانه‌اش.
- **Punctuation:** ، ؛ ؟ and «گیومه».
- **After a number the noun is singular:** «۳ بازی», not «۳ بازی‌ها».
- **Placeholders** (`{name}`) and tags (`<link>`) stay exactly as written. A sentence may reorder them.
- **Never start a line with a Latin word**: it flips the whole line to left-to-right. If a Latin term is unavoidable, put it later in the sentence.
- **A phone number inside text** is wrapped as `⁦۰۲۱ ۱۲۳۴⁩` (left-to-right isolate), or its groups display in reverse.
- **Gender:** Persian has none in «او», so the English "they" comes naturally.
- **Keep the English's strength of evidence.** "May help" stays «ممکن است کمک کند», never «کمک می‌کند». This holds most of all for safety and health.
