# PlayNest as an installable web app (PWA)

The web build is a complete offline app. After the first visit, every screen, picture, font and language works with no
connection, and the app installs to the home screen, dock or taskbar without an app store. The native shells
(docs/NATIVE.md) bundle the same files and skip the service worker.

## What's where

| Piece | File | Notes |
|---|---|---|
| Manifest (English) | `public/manifest.webmanifest` | Linked from `index.html`. |
| Manifest (Persian) | `public/manifest.fa.webmanifest` | Swapped in by the inline script in `index.html` before first paint. Changing language reloads the app, so the swap always matches. Same `id`, so switching language never makes a second app. |
| App icons | `public/icons/` | `node scripts/make-icons.mjs` renders the PNGs from `icon.svg`, plus the four shortcut icons. |
| Install-dialog screenshots | `public/screenshots/` | `npm run screenshots` (after `npm run build`). Phone (narrow, 780×1688) and computer (wide, 1280×800) shots in each language. Not precached. |
| Service worker | generated by `serviceWorker()` in `vite.config.ts` as `dist/sw.js` | Registered in `src/start.tsx`, web builds only. |
| Install button / iOS instructions | `src/components/InstallPrompt.tsx`, `src/platform/index.ts` | Nudge on Today (dismissible), permanent row in Settings. |
| Offline status | `offlineReadiness()` / `watchOfflineReadiness()` in `src/platform/index.ts` | "Works offline" row in Settings → About. |
| Launches | `handleLaunches()` in `src/platform/index.ts` | See "Shortcuts and launching" below. |
| Checks | `src/pwa.test.ts` (manifests), the `offline` steps in `e2e/smoke.mjs` and `e2e/persian.mjs` | |

## The service worker

- **Precache, all of it.** Every built file plus everything in `public/` except `screenshots/`, about a thousand files.
  The code is critical: if it can't be fetched, the install fails and the browser tries again later. A missing picture
  doesn't block the install.
- **Cache first.** The app shell and its files come from the cache, so a stalled network can't leave a blank screen at
  3 a.m. Every navigation in scope gets the app shell, because every screen is behind the `#`.
- **Updates.** A new version activates straight away (`skipWaiting` + `clients.claim`). The open page keeps running the
  old code and shows "PlayNest has been updated · Reload". The previous version's cache is kept until the next update,
  so a tab that's still open can load the chunks it needs. Unchanged public files are copied across, not downloaded
  again. The app checks for a new version whenever it comes back to the foreground.
- **First install.** When the first worker takes over (only once everything is stored), the parent sees "PlayNest now
  works offline".
- **Not handled:** cross-origin requests (there are none; research links open in the browser), non-GET requests and
  range requests.

## Shortcuts and launching

The manifest has four shortcuts (long-press the icon on Android, or the jump list on Windows): Today, Help, tonight's
story and a milestone check-in. `launch_handler` asks for `focus-existing`: if PlayNest is already open, the browser
brings that window forward instead of opening a second one, so a parent keeps their place. `handleLaunches()` then
goes to a shortcut's screen, and leaves the window as it was on a plain launch. Browsers without `launch_handler`
just open the shortcut's URL.

## Data

Everything is in `localStorage` on the device. After a real save, `protectStorage()` asks the browser to keep it under
storage pressure (Safari favours Home Screen apps; Firefox asks). Settings says whether the browser agreed and offers
backup and restore.

## Hosting requirements

Any static host works, as long as it:

- serves over **HTTPS** (service workers and installs need it; `localhost` is fine for testing);
- serves `sw.js` and `index.html` without long caching (`Cache-Control: no-cache`). Browsers skip the HTTP cache when
  they check `sw.js` for updates anyway, and the worker fetches `./` with `cache: 'no-cache'`;
- may cache `assets/*` for a year (`immutable`): their names carry a content hash;
- serves `*.webmanifest` as `application/manifest+json` (most hosts already do).

## Not done, on purpose

- **Push notifications and background sync:** PlayNest has no server and keeps no accounts, so there is nothing to push
  from or sync to.
- **iOS launch images (`apple-touch-startup-image`):** without them, iOS shows a plain screen for a moment at launch.
  iOS wants a separate image for every screen size and orientation, which is a lot of weight for that moment.
- **Share target / file handling for backups:** restoring is two taps in Settings. Accepting shared `.txt` files would
  put PlayNest in every share sheet for text files.

## Regenerating

```bash
node scripts/make-icons.mjs                    # after changing public/icons/icon.svg
npm run build && npm run screenshots           # after a visible change to Today, Play, Help or Stories
npx vitest run src/pwa.test.ts                 # manifests, icons and screenshots still agree
npm run e2e && npm run e2e:fa                  # offline, in both languages
```
